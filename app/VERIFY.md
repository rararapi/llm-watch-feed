# 実機動作確認チェックリスト（実機iPhone + Expo Go）

残タスク 3.5 / 4.4 / 5.4 を実機で確認するための手順。**無料・開発者アカウント不要**。
（6.3 のストア配布は別途。今回はスコープ外）

## 事前準備（人間）

1. iPhone に **Expo Go** をインストール（App Store・無料・サインイン不要）
2. PC と iPhone を **同じ Wi-Fi** に接続
3. 開発サーバを起動:
   ```bash
   cd app
   npm install        # 初回のみ
   npm run tunnel     # WSL2 はこちら（tunnel 経由）。QR コードを表示
   ```
   > **WSL2 では `npm run start`（LAN直結）は不可。** Metro が出す URL が WSL 内部IP
   > （例 `exp://172.20.x.x:8081`）になり iPhone から到達できず "request timed out" になる。
   > `npm run tunnel` は Expo の中継を経由するためネットワーク構成に依存せず繋がる。
4. iPhone の**カメラ**で QR を読み取り → Expo Go でアプリが開く
   （`exp://…` ではなく `exp://*.exp.direct` 形式のURLになっていればtunnelモード）

> データは既定で公開バケットの `models.json` を取得する（インターネット接続でOK、LAN設定不要）。

## 5.4 操作フロー（一覧→詳細→元記事→共有）

- [ ] 一覧が表示され、カードにサムネ・重要度バッジ・ソース・日付・要約が出る

## 4.4 絞り込みの一致（件数で突き合わせ）

まず**期待件数表**を出力（アプリと同じ公開データを使用）:
```bash
cd app
node scripts/filter-parity.mjs
```
→ 「Web/アプリのロジック一致 ✓」と、importance/source ごとの件数・日付グループ件数が出る。

実機で次を確認:
- [ ] 重要度セグメント「すべて / 重要度A / B」を切替 → 件数表示が上表の app と一致
- [ ] ソース絞り込み（右上）で各ソースを選択 → 件数が上表と一致
- [ ] キーワード入力 → タイトル/要約/タグ等に部分一致した記事だけ残る
- [ ] 該当0件のとき「該当する記事がありません」が出る
